# PostgreSQL Workbench — SQL, транзакции и целостность данных

Воспроизводимые сценарии PostgreSQL и Python/Psycopg с Docker-окружением и сквозной проверкой результата отдельным соединением.

## Что реализовано

- CRUD с параметризованными запросами, `RETURNING` и транзакционным выполнением изменений.
- Связанные таблицы, именованные `CHECK`, `UNIQUE`, `FOREIGN KEY`, правила обязательности и удаления.
- Обработка ошибок PostgreSQL через классы Psycopg, SQLSTATE и структурированную диагностику.
- Восстановление соединения через rollback после ошибки транзакции.
- Отдельные базы и роли приложения с минимальными правами в общем PostgreSQL-окружении.
- Повторяемые smoke-проверки зафиксированных данных.

## Что показывает проект

Понимание базы данных на уровне SQL: где гарантируется целостность, как фиксируются и откатываются изменения и почему валидация приложения дополняет правила схемы. Ручной SQL и независимые проверки делают поведение прозрачным. Это применимо к backend-разработке, проектированию схем и диагностике ошибок данных.

## Запуск

Нужен Docker Compose. Из корня репозитория:

```sh
docker compose -f infrastructure/postgres/compose.yaml up -d --wait
./lessons/001-first-crud/smoke.sh
./lessons/002-data-integrity/smoke.sh
```

Каждый smoke пересоздаёт данные своего сценария, выполняет Python-код и проверяет итог через отдельное соединение. Стек: PostgreSQL, Python, Psycopg 3, Docker Compose.
